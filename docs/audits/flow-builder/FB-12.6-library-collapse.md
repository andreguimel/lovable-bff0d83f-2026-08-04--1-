# FB-12.6 — Colapso/Expansão da Library V3

**Status:** ✅ Encerrada
**Data:** 2026-07-20
**Escopo:** Recolher/expandir a Library V3 sem alterar Runtime, Executor, Banco, Serializer, Registry ou contratos persistidos.

## Achado

A infraestrutura de colapso já existia (implementada junto da FB-10.2 e reforçada na FB-11.EXEC). Esta missão **formalizou o contrato**, validou persistência e provou compatibilidade com Inspector, add-on-handle e edge labels.

## Comportamento consolidado

| Item | Como está |
| --- | --- |
| Estado expandido | 300px (≤1024: 260px). Categorias, busca, favoritos, recentes, drag&drop preservados. |
| Estado recolhido | 56px. Rail vertical com ícone por categoria — clique reabre já na categoria escolhida. |
| Toggle | Botão `ChevronLeft` no header (expandido) / `ChevronRight` no rail (recolhido). Ambos com `aria-label`. |
| Persistência | `localStorage["flow-builder.v3.library.collapsed"]` — sobrevive a reload e navegações. |
| Atalho `/` | Reabre automaticamente a Library e foca a busca. |
| Responsivo | `@media (max-width: 1024px)` reduz expandida para 260px; recolhida continua 56px. |
| Canvas | `.fbv2-body` usa `grid-template-columns: auto 1fr auto` — recolher a Library devolve ~244px ao canvas imediatamente. `fit-view` da FB-12.3 recalcula com o novo espaço. |
| Inspector | Não modificado. Convivência: 56 (lib) + canvas + 340 (inspector) ⇒ canvas ≥ 884px em 1280px de viewport. |

## Testes

Novo `src/features/flow-builder/__tests__/library-collapse.test.ts` (6 testes / 14 asserts):

1. Chave de persistência estável e read/write em `localStorage`.
2. Rail renderiza todas as `V3_LIBRARY_CATEGORIES` (≥9).
3. CSS: 300px expandida vs 56px recolhida.
4. Breakpoint ≤1024 preserva colapso.
5. Cálculo geométrico: Library recolhida + Inspector cabem em 1280 com canvas ≥ 800.
6. Botões de recolher/expandir com `aria-label` acessíveis.

**Suite completa Flow Builder:** 222/222 PASS · 1305 asserts · 893ms.
**Typecheck (`tsgo --noEmit`):** limpo.

## Preservações confirmadas

- Runtime, Executor, Banco, Serializer, Registry: **intocados** nesta missão.
- Contratos persistidos: **inalterados** (nenhum campo novo, nenhum shape novo).
- Add-on-handle (FB-12.4) e edge labels (FB-12.5): compatíveis — o Library não intercepta eventos de canvas.

## Evidência visual

Playwright continua bloqueado pelo pipeline SPA→auth→CRM que já foi documentado nas FB-12.4/12.5 (o `/flows/:id` só resolve após múltiplas navegações e o worker de dev perde o contexto). Não foi produzida captura sintética — apenas contrato via testes determinísticos, conforme regra "não inventar evidência".
