# FB-10.3 — Block Cards V3 + Canvas Visual Parity

**Status:** Encerrada
**Data:** 2026-07-18
**Escopo autorizado:** Migrar TODOS os 17 blocos catalogados para o visual V3
(BlockCardV3), sem alterar Runtime, Schema, Serializer, Registry ou Store.

## Entregas

### 1. Migração total para V3 (`canvas/v3/tokens.ts`)
`V3_KINDS` passou de 2 (start/end) para os 17 kinds atuais:
`start`, `end`, `message`, `question`, `send_image`, `send_audio`,
`send_video`, `send_document`, `wait`, `wait_reply`, `condition`, `ai`,
`transfer`, `assign_agent`, `tag`, `http_request`, `webhook`.
Kinds fora dessa lista caem para o card V2 como salvaguarda.

### 2. Humanização de rótulos (`displayKindLabel`)
Mapa determinístico cobre os 17 kinds — nenhum vaza kind técnico
(ex.: `send_audio` → "Envio de áudio"; `wait_reply` → "Espera resposta";
`http_request` → "Chamada de API"). Teste bloqueia underscores em qualquer
rótulo humano.

### 3. Rótulos "Sim/Não" em multi-outputs (`displayHandleLabel` + `BlockNodeV3`)
Blocos com 2+ saídas (hoje só `condition`) ganham rótulos posicionados ao
lado dos PillHandles, com cor semântica (verde para "Sim", vermelho para
"Não"). Blocos single-out NÃO exibem rótulo — evita poluir a lateral.

### 4. Corpo contextual do card
- Preview rico vem do Registry (FB-06) quando o bloco está configurado.
- Quando vazio, mostra hint humano orientando a ação (ex.: "Anexe a imagem
  que será enviada.") — nunca "BLOCO DESCONECTADO" nem acusação genérica.

### 5. Footer discreto
- `start` / `end` orientam conectividade ("Conecte a saída ao primeiro
  passo do fluxo.").
- `condition` reforça leitura das saídas ("Escolha a saída para cada
  resposta.").
- Os outros 14 kinds NÃO exibem footer permanente — elimina o efeito
  "cada peça acusando algo".

### 6. MiniMap oculto quando fluxo é trivial (`FlowCanvasV2.tsx`)
MiniMap só aparece com `nodeIds.length > 2`. Remove o retângulo vazio no
canto inferior direito reportado como poluição visual em fluxos iniciais.

### 7. Estilo dos rótulos de handle (`v3.css`)
Novo bloco `.fbv3-node__hlabel` com variantes `--yes` / `--no` /
`--neutral`, posicionado por `top` calculado dinamicamente conforme
número de saídas.
