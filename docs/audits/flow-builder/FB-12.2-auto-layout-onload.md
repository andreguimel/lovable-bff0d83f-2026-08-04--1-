# FB-12.2 · Auto-layout ao abrir

Data: 2026-07-19
Status: **ENCERRADA**
Escopo: exclusivamente auto-layout ao carregar um fluxo sem coordenadas humanas. Botão "Organizar" continua no toolbar (já existia desde FB-10.3.1). Nada de UX além disso.

## 1. Problema

Fluxos importados, migrados de versões antigas, ou criados por IA/copiloto chegavam com todos os nós em `(0,0)` (ou empilhados na mesma coordenada). Ao abrir, o operador via um pilha ilegível e precisava apertar "Organizar" manualmente. O plano FB-12.2 pedia que isso acontecesse automaticamente na carga inicial.

## 2. Decisão arquitetural — não instalamos `dagre`

O plano original sugeria `dagre`. **Não instalamos.** Motivo:

- Já existe `computeLayeredLayout` em `src/features/flow-builder/canvas/layout.ts` (FB-10.3.2), com:
  - layering longest-path a partir de raízes reais,
  - crossing reduction barycêntrica (sweeps alternados),
  - y-shift barycêntrico para múltiplos incomings,
  - collision pass por coluna,
  - zona de problemas separada para órfãos/starts extras.
- Comportamento **determinístico** garantido por testes (`countCollisions`, `countCrossings`).
- Trocar por `dagre` seria **regressão pura**: nova dependência (~90 KB), perda da zona de problemas, e perda dos testes de determinismo já validados.

O botão "Organizar" no toolbar já usa esse mesmo algoritmo. Reaproveitamos.

## 3. Mudanças

Apenas dois arquivos de produção; um arquivo de teste novo.

### `src/features/flow-builder/canvas/layout.ts`
Novo export `needsAutoLayout(nodes)` — heurística determinística que devolve `true` quando o grafo veio sem posições humanas úteis:

| Condição | Retorno |
|---|---|
| `< 2` nós | `false` |
| todos em `(0,0)` | `true` |
| todos na mesma coordenada (mesmo X e mesmo Y) | `true` |
| ao menos um nó em posição distinta | `false` |

Sem alocações grandes, O(N), sem side effects.

### `src/features/flow-builder/FlowStudioV2.tsx`
No `useEffect` de carga inicial (linhas 128-171), após `loadFromSnapshot`, chama `needsAutoLayout(snapshot.nodes)`. Se `true`, computa `computeLayeredLayout` e aplica via `applyLayout`. O autosave (debounce 800ms) persiste as posições organizadas na primeira gravação subsequente — próximo open já não dispara auto-layout.

Nenhuma outra rota, componente, store slice ou schema foi tocado.

## 4. Aceite

Aceite do plano: "fluxos importados abrem em colunas verticais legíveis." ✓

Cenários cobertos pelos testes:
- START → MESSAGE → END com todos em `(0,0)` → auto-organiza, 0 colisões, X estritamente crescente por layer.
- 8 nós em cadeia → posições determinísticas (mesma entrada = mesma saída).
- Fluxo já disperso → `needsAutoLayout` retorna `false`, layout preservado.
- Grafo com 1 nó → não faz nada.
