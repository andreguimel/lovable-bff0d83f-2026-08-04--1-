## 1. Arquitetura implementada

- **Definição do bloco** (`src/features/flow-builder/blocks/definitions.ts`)
  - `kind: "menu"`, categoria `channels`, ícone `ListTree`, accent verde-água.
  - Campos: `body` (textarea, obrigatório), `options` (novo tipo `menu_options`, min 2 / max 10, IDs `opt_<hash>` estáveis), `max_attempts` (1..5, default 2), `invalid_message`.
  - `getHandles(data)` dinâmico: 1 entrada + 1 saída por opção com ID estável + saída fixa `invalid`.
  - `validate(d)`: exige body, ≥2 opções, labels distintos (case-insensitive) e IDs únicos.
- **UI de configuração** (`src/features/flow-builder/fields/renderer.tsx`)
  - Novo case `menu_options`: adiciona/remove/edita labels; IDs preservados pelo React `key={id}` — editar label **não** altera o ID.
- **Handles dinâmicos** (`src/features/flow-builder/canvas/v3/BlockNodeV3.tsx`)
  - Usa `def.getHandles(data)` quando disponível, fallback para `meta.handles` estático.
- **Visual V3** (`src/features/flow-builder/canvas/v3/tokens.ts`)
  - `menu` incluído em `V3_KINDS`, categoria mapeada para `menu`, rótulo humano `Menu de opções`.
- **Library V3** (`src/features/flow-builder/library/v3/categories.ts`)
  - Categoria `menu` deixou de ser `comingSoon` — bloco aparece na paleta lateral sem chip "Em breve".
- **Executor de produção** (`src/lib/flow-executor.server.ts`)
  - `menuNode` registrado em `NODE_PLUGINS.menu`.
  - Estado por-run em `variables.__menu = { nodeId, attempts }` — escopo por node.
  - Reuso do mecanismo `WAITING_REPLY`; retomada pelo mesmo caminho canônico via `flow-resume-inbound.server.ts` (não cria run paralelo).
  - **Bug corrigido dentro do escopo (High)**: `variables.reply` é objeto `{id,type,body,...}` — a versão inicial fazia `String(reply)` e recebia `"[object Object]"`. Executor agora extrai `.body` (ou aceita string bruta).

## 3. Contrato Runtime

- Primeira entrada: envia `body\n\n1) label...`; grava mensagem outbound com `media_metadata.menu=true` e `flow_node_id`; pausa em `WAITING_REPLY`; grava `variables.__menu` e `variables.reply=null` no `flow_runs`.
- Retomada: `flow-resume-inbound.server.ts` injeta `variables.reply = { body, ... }`, chama `executeRun` mantendo `runId`, `conversation_id`, `contact_id`, `company_id`.
- Casamento: número (1..N, tolerante a `1.` / `1)`) ou texto exato case-insensitive.
- Falha reconhecível: incrementa `attempts`, reenvia `invalid_message`, volta a `WAITING_REPLY` com o mesmo `nodeId` no `__menu`.
- Excedeu `max_attempts`: `nextHandle = "invalid"`, limpa `__menu`, segue pelo handle `invalid`.
- Isolamento: ao resolver, `__menu` é setado como `null` — nenhum estado vaza para um segundo Menu no mesmo fluxo.

## 5. Health / Publicação

Cobertura em `menu-block.test.ts`:

- body vazio → erro impeditivo (`path: body`)
- <2 opções → erro impeditivo (`path: options`)
- Opções com label duplicado → erro impeditivo
- IDs duplicados ou ausentes → erro impeditivo
- Config válida → `valid: true`

O motor de validação (`validation/engine.ts`) usa `blockRegistry.validate(kind,data)` — qualquer erro do Menu bloqueia publicação via `canPublish=false`.

## 6. Correlação e estado

Confirmado por leitura de `flow-executor.server.ts` + `flow-resume-inbound.server.ts` + suíte E2E:

- Não instancia executor paralelo — o resume passa pelo `executeRun` canônico.
- `flow-resume-inbound` faz UPDATE atômico `WAITING_REPLY → RUNNING` (`.eq("state","WAITING_REPLY")`) — sem race.
- `conversation_id`, `contact_id`, `company_id` vêm do run existente e não são recriados.
- `variables.__menu` carrega `nodeId` — se o executor entrar em Menu com `nodeId` diferente, ignora o state legado (guard testado).

## 10. Limitações e riscos restantes

- Resposta apenas por texto/número. Áudio como resposta é reconhecido como reply, mas não casa opções (fica como "inválido") — comportamento esperado; documentar quando abrirmos FB-10.4B.
- Não há botões interativos do WhatsApp Cloud (list/reply buttons) — apenas texto numerado. Consistente com a decisão RC3.1 de manter compatibilidade máxima; a upgrade para botões nativos fica em roadmap fora do FB-10.4.
- Editar `option.id` manualmente no banco quebra a edge — protegido no UI (IDs opacos), mas não há migration para reconciliação retroativa.
