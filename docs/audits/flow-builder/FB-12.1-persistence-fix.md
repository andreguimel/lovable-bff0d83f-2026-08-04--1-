## 1. Bug (P0) — como o fluxo falhava

Toast `"Erro ao salvar"` ao tentar salvar qualquer fluxo contendo um bloco introduzido em FB-10.4A/B/C/D. Origem confirmada por leitura direta de `src/lib/flows.functions.ts:206` (VALID_NODE_KINDS) — o enum zod da server function `saveFlowGraph` **não incluía** os kinds novos, então o `.parse(input)` rejeitava o payload antes de qualquer INSERT.

Kinds rejeitados: `menu`, `action`, `flow_connection`, `randomizer`.
Kinds citados na autorização e classificação:
- `send_file` · **N/A** — nunca existiu na plataforma; Zenda usa `send_document`. Confirmado varrendo a árvore (`rg send_file` retorna zero ocorrências fora de referências informais).

## 2. Causa arquitetural (não apenas patch)

Havia **quatro fontes de verdade paralelas** para "quais tipos de bloco existem":

| Camada | Local | Antes |
|---|---|---|
| UI / Registry | `src/features/flow-builder/blocks/definitions.ts` (`BLOCKS[].kind`) | 21 kinds |
| Visual V3 | `src/features/flow-builder/canvas/v3/tokens.ts` (`V3_KINDS`) | 21 kinds hardcoded (por sorte sincronizado) |
| Runtime | `src/lib/flow-executor.server.ts` (`NODE_PLUGINS`) | 26 entradas (canônicos + aliases) |
| Persistência | `src/lib/flows.functions.ts` (`VALID_NODE_KINDS`) | **19 entradas — 4 canônicos faltando** |

Cada camada tinha seu próprio literal `as const`. FB-10.4A/B/C/D acrescentou blocos em três camadas e esqueceu a quarta. Nenhum teste anterior exercitava o zod schema da persistência com o conjunto de kinds do Registry — a suíte de FB-10.4 provava executor + registry, não round-trip até o schema de save.

### Correção arquitetural (mínima e segura)

Novo módulo canônico único: `src/features/flow-builder/blocks/kinds.ts`

```ts
export const CANONICAL_BLOCK_KINDS = [ ...21 canônicos... ] as const;
export const LEGACY_KIND_ALIASES   = [ ...5 aliases legados aceitos pela persistência... ] as const;
export const PERSISTABLE_NODE_KINDS = [...CANONICAL_BLOCK_KINDS, ...LEGACY_KIND_ALIASES] as const;
```

Todos os consumidores derivam desse módulo:
- `flows.functions.ts` → `const VALID_NODE_KINDS = PERSISTABLE_NODE_KINDS;`
- `canvas/v3/tokens.ts` → `V3_KINDS = new Set(CANONICAL_BLOCK_KINDS);`

Nenhuma migração de banco: `flow_nodes.node_type` é `text` (não é enum Postgres). O gate era exclusivamente o zod.

## 6. Publicação

`validateGraphForPublish` (linhas 1348-1373 do executor) não usa whitelist de kinds — só valida start único, sem edges órfãs e leaves apenas `end`. O gate de kinds era exclusivamente `saveFlowGraph.inputValidator`, que agora aceita todos os canônicos. **Publicação desbloqueada**.
